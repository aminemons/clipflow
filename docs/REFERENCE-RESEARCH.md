# Reference research for Clipflow

Research date: 2026-09-20. Sources are the repositories' actual tracked source files, manifests, and licenses. The recommendations below describe behavior and architecture; no reference code or assets should be copied.

## Evidence by capability

### Upload, YouTube/link import, and storage

VideoSplitter validates YouTube URLs, tries YoutubeExplode, retries cipher/decrypt errors, and falls back to invoking yt-dlp. It also probes local files with FFprobe and generates thumbnails. This is a robust local import pattern, but the bundled desktop path and external downloader should be treated as optional adapters. Source: [VideoService.cs](https://github.com/isaacrlevin/VideoSplitter/blob/main/src/VideoSplitter/Services/Clipping/VideoService.cs).

ClipForge's upload path streams `UploadFile` in 4 MiB chunks to a generated disk path, rejects unsupported extensions and max size, then probes metadata and creates a poster frame. Link import returns `202`, stores `downloading`, and updates progress in a background task. Sources: [videos.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/api/videos.py), [models.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/models.py).

Zitro's browser storage separates object storage from a `media_files` row, namespaces paths under `user.id`, and returns signed URLs. Its editor also stores projects and Blobs in IndexedDB for local continuity. Sources: [useStorage.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/hooks/useStorage.ts), [editorStorage.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/lib/editorStorage.ts).

### Jobs and recovery

ClipForge is the strongest reference for a local FastAPI backend: `Job` and `Part` are durable SQLite rows, status/progress/message/error fields are explicit, cancellation is supported, and startup requeues `queued` or `running` jobs. The queue is in-process and one worker, so deployment must keep one persistent backend instance. Sources: [models.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/models.py), [jobs.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/api/jobs.py), [queue.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/workers/queue.py).

Zitro's `processing_jobs` model has realtime Supabase updates, typed active/completed/failed states, and cancellation. Its advantage is multi-client status visibility; its cost is a hosted database and auth dependency. Source: [useJobs.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/hooks/useJobs.ts).

### Transcription and highlights

VideoSplitter makes the provider a factory with local Whisper.NET and Azure Speech. Its local provider serializes model download and reports progress while downloading/loading. Source: [WhisperTranscriptProvider.cs](https://github.com/isaacrlevin/VideoSplitter/blob/main/src/VideoSplitter/Services/Transcript/TranscriptProviders/WhisperTranscriptProvider.cs).

ClipForge extracts 16 kHz mono WAV, lazy-loads faster-whisper in a thread, emits timestamped segments and progress, and treats transcription as best effort. Its viral implementation uses a useful three-tier fallback: Groq transcript rating, transcript heuristics, or audio loudness + scene-cut density. Sources: [transcription.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/services/transcription.py), [viral.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/services/viral.py), [cloud_stt.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/services/cloud_stt.py).

Zitro's URL transcription is a paid path: the Edge Function checks an authenticated user and active subscription, resolves YouTube/TikTok/Instagram URLs through Apify, enforces OpenAI's 25 MB limit, and calls `whisper-1`. Source: [transcribe-url/index.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/supabase/functions/transcribe-url/index.ts). Its browser transcription client extracts audio in an `OfflineAudioContext` when a video exceeds that limit. Source: [transcriptionService.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/services/api/transcriptionService.ts).

### Reframe, editor, subtitles, and export

ClipForge's server-side renderer is a close fit for the current app: one FFmpeg render function composes geometry, subtitles, and draggable overlays; preview uses the same geometry without burning text, which keeps preview and export aligned. The schema expresses source vs 9:16 reel, crop vs blurred fit, quality, resolution, format, overlays, and subtitle position. Sources: [ffmpeg.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/services/ffmpeg.py), [schemas.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/schemas.py), [pipeline.py](https://github.com/SJbuilds04/Clip-Forge/blob/main/backend/app/workers/pipeline.py).

Zitro's browser FFmpeg implementation proves that local/WASM export can work, but requires same-origin core files and COOP/COEP headers for `SharedArrayBuffer`; it has explicit load timeout/progress/cleanup behavior. Source: [ffmpegEngine.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/lib/ffmpegEngine.ts). Its export Edge Function does not render video itself: it consumes credits, creates a job, and accepts a base64 result rendered client-side. Source: [export-video/index.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/supabase/functions/export-video/index.ts).

VideoSplitter's extraction service demonstrates server/local FFmpeg filters for vertical crop, blur background, letterbox, split-screen modes, and subtitle burn-in. Source: [VideoExtractionService.cs](https://github.com/isaacrlevin/VideoSplitter/blob/main/src/VideoSplitter/Services/Clipping/VideoExtractionService.cs).

### Auth, persistence, publishing, and monetization

Zitro has concrete Supabase Auth session handling and a plan/paywall model. The export and OpenAI proxy functions require bearer authentication and an active subscription; the export path consumes 20 credits and stores a signed URL with a seven-day expiry. Sources: [export-video/index.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/supabase/functions/export-video/index.ts), [openai-proxy/index.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/supabase/functions/openai-proxy/index.ts), [useSubscription.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/hooks/useSubscription.ts). Square payment tokenization is wired to a Supabase Edge Function. Source: [squareService.ts](https://github.com/KuchikiRenji/Saas-platform-Zitro/blob/main/src/services/api/squareService.ts). These are paid/external service paths, not prerequisites for a local Clipflow build.

VideoSplitter has real Google OAuth token exchange, refresh, channel validation and YouTube upload, plus publisher abstractions for TikTok and Instagram. Source: [YouTubeShortsPublisher.cs](https://github.com/isaacrlevin/VideoSplitter/blob/main/src/VideoSplitter/Services/SocialMediaPublishers/YouTubeShortsPublisher.cs). This is a later integration layer; it should not be coupled to rendering.

## Adoption decisions for Clipflow

1. Keep Vite + FastAPI/FFmpeg and the one-worker default. Adopt durable job records and explicit progress/errors/cancellation. Clipflow retains its JSON store with migration/recovery backups rather than adding SQLAlchemy in this release. Interrupted jobs become retryable errors; automatically replaying a paid provider request after restart is deferred.
2. Preserve complete-source duration segmentation separately from selective highlights. Adopt a shared FFmpeg renderer for proof and export geometry/captions/effects. Fixed clip-count splitting is a possible later feature, not implemented in this rebuild.
3. Make transcription and highlight ranking optional. Prefer local faster-whisper first for offline use, allow Groq as an opt-in accelerator, and retain signal/heuristic ranking when no key/model is available. Never make an API key mandatory for basic clipping.
4. Keep server project/job/export persistence authoritative and browser state limited to editor preferences and bounded undo history. IndexedDB media caching is deferred because duplicating large videos would worsen the current storage constraint.
5. Use direct local disk/download exports now. Model a storage adapter so S3/Supabase can be added later; if Supabase Auth is introduced, keep it optional and map its user ID to project ownership without requiring hosted media for local mode.
6. Defer social publishing and paid credits until render/recovery behavior is stable. When added, isolate OAuth providers behind a publisher interface like VideoSplitter and keep token refresh/errors separate from the FFmpeg job.
7. Do not import Zitro's code/assets because the repository has no license. VideoSplitter and ClipForge are permissively licensed, but reimplementation remains safer and any copied MIT/Apache material would require preserving its notices and complying with each license.

## Official competitor documentation signals

- [OpusClip: ClipAnything](https://www.opus.pro/clipanything) and [editor overview](https://help-center-preview.eng.opus.pro/) documents multimodal clipping from visual, audio, and sentiment cues, plus manual reframe, captions, trim/extend, overlays, transitions, filler removal, AI B-roll/voiceover, saved projects, publishing, and XML export. For Clipflow this supports prioritizing explainable highlight scoring, editable reframe/caption controls, and a durable project/result view before adding a full timeline editor.
- [Descript: Export subtitles](https://help.descript.com/hc/en-us/articles/10255811669773-Exporting-subtitles) distinguishes downloadable SRT/VTT subtitles from captions burned into the video and exposes line/card constraints. Clipflow should preserve both a timed subtitle track and an optional burned-in render path.
- [Descript: share pages and export](https://help.descript.com/hc/en-us/articles/10255817744653-Publish-content-with-Descript-web-links) shows the value of a durable share/download result with privacy, resolution, transcript display, and expiry/access policy. This is a later hosted-output feature; local export should remain first-class.

## Source integrity notes

All observations above were made from first-party repository files, manifests, and licenses. README feature claims were accepted only when corroborated by implementation files. External provider behavior and pricing can change; treat Groq, OpenAI, Apify, Square, Google Drive, and social API credentials as optional adapters with explicit failure states.
